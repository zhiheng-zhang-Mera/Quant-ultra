# Experiment and Benchmark Governance

Formal experiments are registered before completion with a unique `EXP-` ID, hypothesis, objective, controlled/changed variables, parent experiment, data version, code version, parameter version and report references. Completion records `ACCEPT`, `HOLD`, or `REJECT`; rejected work requires a failure class. Events are append-only and hash-chained.

The comparable benchmark contract requires one identical date index, data/PIT universe, capital base, cost model, board lot, leverage limit and trading constraint set. Its universe includes passive, classic rule, factor and ML candidates plus current and historical Quant-Ultra roles. Git and data versions are embedded in the manifest.

External open-source rankings and cross-market published figures are auxiliary context only. They cannot support a core performance advantage claim because their data, era, cost and constraints differ.

A production parameter must link back to an accepted experiment chain. Legacy narrative results that lack a formal ID remain labelled legacy evidence and cannot be silently rewritten into registered experiments.
