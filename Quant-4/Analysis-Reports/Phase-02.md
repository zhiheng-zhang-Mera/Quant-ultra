# Phase_2_Data_Slicing：数据防漏与切分深度解析

## 概述

Phase_2（Data Slicing & Validation）是 Quant‑4 系统的**时序数据隔离与交叉验证分区层**，负责在严格杜绝未来函数（Look‑ahead Bias）和信息泄露（Information Leakage）的前提下，将 Phase_1 产出的全时序资产面板按时间顺序划分为训练、验证和测试子集。其核心创新在于引入**清洗（Purged）**与**禁运（Embargo）**机制，基于自相关函数（ACF）动态估算市场记忆长度，强制在相邻分区之间留出无数据隔离带，从而从根本上消除因序列相关性导致的验证分数虚高问题。

Phase_2 的设计直接呼应 Quant‑4 系统手册中“阶段二”的专业要求，其与主框架的 `data_bus`、`context_io` 和 `audit_logger` 深度联动，为下游模型训练提供可靠的时空边界。

---

## 模块总览与协作关系

| 文件 | 核心职责 | 依赖关系 |
|------|----------|----------|
| `__init__.py` | 暴露 `execute` 入口，供主引擎调度 | 被 `main_engine.py` 调用 |
| `config.py` | 定义切片比例、禁运最小周期、ACF 分析参数、熔断阈值 | 被所有子模块引用 |
| `acf_analyzer.py` | 计算双市场（A股/美股）收益率序列的自相关滞后阶数（ACF Lag） | 依赖 `data_bus` 和 `statsmodels` |
| `step2_1_slicing.py` | 基于 ACF 滞后和固定持有期，执行 Purged K‑Fold 切分，生成各分区日期列表 | 依赖 `acf_analyzer`、`config` |
| `step2_2_validation.py` | 审查切片间的时序隔离带宽度，确保物理不重叠，触发硬熔断或日志警告 | 依赖 `config`、`audit_logger` |
| `step2_data_slicing.py` | 串联上述步骤，执行上下文同步、内存冲刷、日历自愈，并标记 `slices_isolated` | 聚合所有子模块 |

## 各模块详解

### 1. `config.py` —— 切片与禁运参数中心

**功能**  
提供 Phase_2 运行的静态阈值：
- 五段式切分比例 `DEFAULT_SLICING_RATIOS = [0.50, 0.60, 0.70, 0.85]`，分别对应 Train‑A、Train‑B1、Train‑B2、Validation 的结束比例（Test 为剩余部分）。
- 保底持有期 `DEFAULT_HOLDING_PERIOD = 5`（交易日），用于计算禁运窗口的下限。
- 禁运最小周期 `DEFAULT_EMBARGO_MIN = 5`。
- ACF 相关参数：`MIN_DAYS_FOR_ACF`（100 天）、`ACF_NLAGS`（10）、`ACF_ALPHA`（0.05）、`MAX_SAMPLE_ASSETS`（50）。
- 熔断阈值 `MIN_SLICE_WARN_LEN`（10）和 `MIN_SLICE_CRIT_LEN`（5），用于检查分区长度是否过短。

**设计亮点**  
- 参数集中且带有明确注释，易于调整。
- 将 ACF 分析参数与切片参数分离，职责清晰。

**潜在缺陷**  
- 所有参数硬编码，未从外部配置加载，与主引擎的 `default_param.yaml` 脱节，无法实现运行时的动态覆盖。
- 切片比例为固定值，无法根据数据长度自适应调整，在长周期或短周期回测中可能不够灵活。

### 2. `acf_analyzer.py` —— 动态 ACF 滞后计算

**功能**  
- 从 `assets` 中分别抽取 A 股和美股两类资产，各取前 50 只（`MAX_SAMPLE_ASSETS`）作为样本。
- 对每只样本资产加载约 500 个交易日的历史数据（位于整个回测区间的前 60% 位置，避免使用未来数据）。
- 计算该资产的实际对数收益率序列（优先使用 `actual_log_return`，其次 `log_return`，若不存在则通过收盘价自行推导）。
- 使用 `statsmodels.tsa.stattools.acf` 计算前 10 阶自相关系数，找出在 95% 置信区间下显著非零的最大滞后阶数。
- 分别汇总两类资产的显著滞后阶数，取中位数作为该市场的 `lag`。
- 最终全局禁运窗口 `max_lag = max(lag_cn, lag_us)`（若某市场样本不足，则返回 1）。

**设计哲学**  
- 分布式采样思想：分别对两个市场独立评估，再聚合取最大值，体现多市场差异性。
- 仅使用回测区间前 60% 的数据计算 ACF，避免使用未来的信息（尽管 ACF 本身来自历史，但该设计符合 PIT 精神）。
- 样本限制（50 只）防止因资产过多导致 IO 爆炸。

**优点**  
- 动态估算而非固定常数，使禁运窗口具有统计学依据，能适应不同市场特征。
- 错误处理周全：对数据缺失、异常值进行了捕获和降级，不会因单只资产失败而中断流程。

**客观缺陷**  
- 仅使用前 60% 区间计算 ACF，若市场结构在后半段发生结构性变化（如波动率 regime 切换），则估算的滞后可能不具代表性。
- `_calculate_market_lag` 中中位数取整为 `int(np.median(lags))`，但 `lags` 是整数列表，直接取中位数可能造成偏小（例如中位数 2.5 取整为 2），而使用 `ceil` 更保守。
- 美股资产的识别依赖 `'.US' in a or any(c.isalpha() for c in a.split('.')[0])`，该逻辑简单但可能误判（如部分 A 股代码包含字母？实际 A 股纯数字，美股含 `.US`，此判断尚可，但若数据源中有其他后缀则可能分类错误）。
- 未考虑停牌对收益率序列连续性的影响，可能导致 ACF 估计偏差。

### 3. `step2_1_slicing.py` —— Purged K‑Fold 切分执行

**功能**  
- 首先调用 `compute_dynamic_acf_lag` 获得全局禁运窗口 `embargo_window`，取 `max(holding_period, max_lag, embargo_min)`。
- 基于配置的切片比例 `slicing_ratios`，计算原始分界索引（A 股日历长度 * 比例）。
- 对每个市场（A 股和美股）的日历，分别生成五个分区：
  - **Train‑A**：从开头到 `原始A_end - embargo_window`
  - **Train‑B1**：从 `原始A_end + embargo_window` 到 `原始B1_end - embargo_window`
  - **Train‑B2**：从 `原始B1_end + embargo_window` 到 `原始B2_end - embargo_window`
  - **Validation**：从 `原始B2_end + embargo_window` 到 `原始Val_end - embargo_window`
  - **Test**：从 `原始Val_end + embargo_window` 到结尾
- 将分区列表存入 `context['slices']`（键为 "CN" 和 "US"），同时记录原始索引边界。
- 若某分区长度小于 `MIN_SLICE_WARN_LEN`（10 天），触发审计事件 `SLICE_TOO_SHORT_WARNING`。

**设计亮点**  
- 严格的双向禁运：每个分区尾部会扣除 `embargo_window`，同时下一个分区的头部也从上一个原始边界后移 `embargo_window`，确保两个分区之间至少有 `2*embargo_window` 的隔离（实际计算中可能略小于两倍，但至少保证 `embargo_window` 的间距）。
- 双市场独立切分但使用相同的比率和禁运窗口，保证 A 股和美股在逻辑上对齐，便于跨市场因子对齐。
- 原始索引记录可追溯，便于审计。

**客观缺陷**  
- 若回测区间总天数不足以容纳所有分区（即 `embargo_window` 过大导致某些分区为空），则切片列表可能为空，后续验证会触发熔断。
- 对 A 股和美股使用相同的切分比例，但两者交易日数量可能不同（如美股节假日不同），导致即使比例相同，绝对日期不同，但仍保持相对位置对齐，这本身合理；但若市场间存在高度异步性，可能影响跨市场策略。
- 未对 `slicing_ratios` 进行排序或合法性检查，若用户配置错误（如倒序），可能导致非预期行为。

### 4. `step2_2_validation.py` —— 隔离带硬性审查

**功能**  
- 遍历每个市场的相邻分区对（Train‑A → Train‑B1 → ... → Validation → Test）。
- 计算前一分区的最后一天和后一分区的第一天在日历中的索引差 `delta_days`（若日历中找不到日期，则用日期间隔折算）。
- 若 `delta_days < embargo_window`，则记录 `EMBARGO_VIOLATION_CRITICAL` 审计事件并抛出 `RuntimeError`，终止流水线。
- 同时检查每个分区长度是否小于 `MIN_SLICE_CRIT_LEN`（5 天），若小于则同样抛出异常（美股的非 Train‑A 分区允许为空，但其他分区必须满足长度要求）。

**设计哲学**  
- 双保险机制：既检查了间距，也检查了有效样本数，确保后续模型训练有足够数据。
- 美股非核心分区的空值宽容处理，体现对多市场差异性的尊重（美股可能仅作为特征来源，不必严格对齐）。

**优点**  
- 熔断机制强硬，杜绝任何信息泄露的可能性，保障回测学术诚信。
- 审计日志记录违规细节，便于调试。

**客观缺陷**  
- 当日历中无法精确索引日期时，使用 `(first_right - last_left).days // 7 * 5` 进行粗略折算，假设每周 5 个交易日，但 A 股和美股节假日不同，折算误差可能较大，极端情况下可能误报或漏报。
- 检查仅针对相邻分区，但未验证跨多个分区的整体单调性（例如 Train‑A 的结束日期是否确实早于 Validation 的开始日期等），这些在相邻检查中已隐含，但若分区列表为空，则逻辑跳过。
- 美股非 Train‑A 分区允许为空，但若为空，后续模型可能无法使用美股数据，该决策依赖外部逻辑，此处未明确定义。

### 5. `step2_data_slicing.py` —— 主控编排器

**功能**  
- **上下文同步**：若 `pipeline_context` 中无 `assets`，但 `data_bus.get_universe()` 有数据，则从总线同步资产列表，消除冷启动不一致。
- **内存冷冲刷**：清空 `data_bus._cache`，防止 Phase_1 残留的脏数据污染当前切分逻辑（尤其是 `data_bus` 中可能缓存了旧日期或错误值）。
- **日历自愈**：若上下文中缺失 `trading_days_dt_cn` 或 `trading_days_dt_us`，则调用 `_determine_start_year` 从缓存的历史数据中推断最早年份，然后通过 `data_bus.manager` 拉取交易日历，注入上下文。
- 依次调用 `run_moving_window_slicing` 和 `run_purge_and_embargo_validation`。
- 设置 `pipeline_context['slices_isolated'] = True`，标记切片隔离完成。

**设计亮点**  
- 主动防御：清除 `data_bus._cache` 是一个极具工程意识的举措，避免之前阶段（如 Phase_1 的 `append_atom`）写入的测试数据或中间数据影响 Phase_2 的日期索引判断。
- 日历自动补全：当历史上下文不完整时，能根据已有缓存数据自动推断起始年份，实现“自愈”，降低用户配置负担。

**客观缺陷**  
- `_determine_start_year` 仅读取前 100 个资产（或缓存目录中的前 100 个文件）的 `_history.parquet` 文件，若这些文件不包含足够早的数据，则推断年份偏晚，可能导致日历起始日过迟，切掉早期数据。
- 清空整个 `data_bus._cache` 可能影响其他同时运行的模块（但 Phase_2 是串行执行，无并发问题），但若 `data_bus` 被其他模块共享（如主引擎中为全局），则可能造成不必要的重新加载。
- 日历自愈仅使用 `data_bus.manager.fetch_trading_calendar`，但未指定数据源，默认可能返回 A 股日历，对美股日历未做区分（此处将两个市场的日历设置为相同，显然不合理，因为 A 股和美股交易日不同）。这是一个严重缺陷：`trading_days_dt_us` 被赋值为与 `trading_days_dt_cn` 相同的日历，导致美股切片对齐错误。

## 整体评价与改进方向

### 系统优势
- **学术严谨性**：Purged K‑Fold + Embargo 机制是量化金融领域最先进的数据分割方法，有效避免信息泄露。
- **动态自适应**：ACF 动态估算禁运窗口，而非硬编码常数，体现数据驱动理念。
- **双市场并行**：同时处理 A 股和美股，且独立计算各自的 ACF 滞后，尊重市场异质性。
- **强校验与熔断**：在切片阶段即进行严格的隔离带审查，防止下游模型在污染的数据上训练。

### 当前痛点
- **日历自愈 Bug**：美股日历被错误赋值为 A 股日历，导致美股切片完全无效，必须修复。
- **配置硬编码**：切片比例、ACF 参数等均固化在 `config.py`，无法由外部 YAML 覆盖，降低灵活性。
- **性能开销**：ACF 分析需加载 50 只股票的历史数据并计算自相关，在资产数量庞大时仍有一定 IO 消耗（但已限制样本数）。
- **ACF 采样窗口固定**：仅使用前 60% 区间，可能不适应市场变化；可考虑使用滚动窗口或近期数据。
- **美股空分区宽容处理可能导致下游模型无法利用美股信息，但未提供明确的分支逻辑**。

### 未来演进
- **修复日历自愈逻辑**：应分别获取 A 股和美股日历，或从 `data_bus.manager` 中根据市场类型查询。
- **配置外部化**：将 `config.py` 中的参数迁移到主 YAML 配置，允许运行时覆盖，提升实验灵活性。
- **ACF 窗口动态化**：可改为基于全历史但确保 PIT（例如在切分点之前的历史计算），或使用指数加权。
- **支持更多切分模式**：除固定比例外，可支持时间窗口滑动或基于事件（如经济周期）的自适应切分。
- **增强缓存与复用**：ACF 计算结果可缓存，避免重复运行。

---

## 结语

Phase_2 作为 Quant‑4 系统的时序防护层，通过严谨的 Purged/Embargo 机制和动态 ACF 估算，为下游模型训练提供了无偏的时空划分。其设计体现了量化研究对数据泄露零容忍的核心价值观。尽管存在个别 Bug 和配置硬编码问题，但其架构思路极具参考价值，为构建可靠的量化回测系统奠定了坚实的时间序列基础。修复上述缺陷后，Phase_2 将更具工业化生产品质。
