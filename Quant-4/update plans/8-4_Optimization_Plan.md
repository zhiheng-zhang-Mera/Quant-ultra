# Quant-Ultra (Quant-4) 工业级量化引擎全面优化与重构方案计划书

## 一、 项目背景与优化总目标

### 1.1 系统现状与核心痛点
Quant-Ultra（Quant-4）是一套涵盖数据基建、特征工程、机器学习、运筹优化、物理回测到 MLOps 实盘运维的 11 阶段全栈量化交易系统。尽管系统在理论设计上具备高度的专业性（如 PIT 防穿越、FSM 状态机回测、Black-Litterman 凸优化等），但在落地执行与代码闭环层面仍存在若干阻碍实盘部署的致命痛点：

1. **数据真实性与时空穿越风险**：部分基础数据（如历史 ST 状态、做空融券成本）未完全按 Point-in-Time (PIT) 时间线提取；特征生成模块存在单时点截面与全时序面板的格式断层，且存在使用随机数占位伪造数据的现象。
2. **撮合时序与价格语义错位**：回测引擎部分模块仍保留“同日信号-同日价格”成交的理想化假设，未彻底迁移至标准的下一交易日（$T+1$）开盘订单撮合队列。
3. **风控硬杀伤与审计断流**：影子对账与黑天鹅压力测试抛出的红线警告未真正与物理交易阻断逻辑（Hard-Kill Switch）串联；试错次数（`num_trials`）因参数断层未透传至过拟合审计模块（DSR）。
4. **调试代码与硬编码残留**：存在切片剪裁等调试性残留代码；配置参数散落在各个阶段的子模块中，缺乏统一的配置中心与安全白名单校验。

### 1.2 总体优化目标
本优化方案旨在将 Quant-4 从“研究验证沙盒”彻底升级为**具备生产级鲁棒性、物理真实性与金融级安全保障的无人值守量化投资系统**。

* **数据可靠性**：实现 100% 严格 PIT 时间线数据提取，彻底消除未来函数与伪造数据污染。
* **物理高保真**：构建严格的 $T 	o T+1$ 订单执行时序与包含冲击滑点、停牌截断、整手限制的有限状态机（FSM）。
* **风控绝对化**：实现“失败即关闭（Fail-Closed）”机制，确保压力测试、对账偏差与漂移监控具备一票否决权与物理硬杀伤能力。
* **架构规范化**：建立统一配置中心、运行态缓存指纹、DAG 拓扑契约校验以及 CIO 多智能体参数提案治理闭环。

## 二、 分阶段业务逻辑优化与功能重构方案

### Phase 1: 数据基建与生存矩阵重构 (Data Foundation)
* **优化目标**：构建彻底消除生存者偏差与停牌/退市幽灵收益的数据底座。
* **具体重构方案**：
  1. **PIT 状态动态对齐**：重构标的筛选与状态识别逻辑，所有 ST 状态、停牌事件、退市公告均通过真实披露日历（PIT）进行回溯，严禁使用当前截面快照替代历史状态。
  2. **生存矩阵 (Survivorship Matrix) 高效化**：优化标的存续状态矩阵的构建算法，采用向量化并行映射替代双重循环，提升大规模标的池的处理性能。
  3. **多源行情一致性校验**：引入跨数据源价差与复权因子对账机制，对异常跳空与除权除息数据自动标记并拉响数据质量告警。

### Phase 2: 时间切片与动态禁运隔离 (Data Slicing)
* **优化目标**：彻底隔离训练集、验证集与测试集，防范自相关性导致的数据泄漏。
* **具体重构方案**：
  1. **多市场日历独立自愈**：彻底解耦 A 股、港股与美股的交易日历逻辑，确保跨市场切片计算时各自调用独立且经过校验的交易日历。
  2. **动态 ACF 衰减与 Embargo 计算**：将自相关系数（ACF）的采样窗口扩展至全量训练区间，并根据因子平稳性动态计算自适应禁运期（Embargo Length），强制阻断时序重叠。

### Phase 3: PIT 特征工程与全时序面板 (PIT Features)
* **优化目标**：构建高维度、无穿越的全时序特征面板，清除任何占位伪数据。
* **具体重构方案**：
  1. **全时序面板张量化**：重构特征生成管道，由“单时点横截面”升级为标准的三维时序面板张量 $(T 	imes N 	imes F)$，直接适配下游机器学习模型训练。
  2. **伪数据彻底清理与缺失处理**：全面清理私有特征生成模块中的随机数占位逻辑。对缺少原始数据源的因子，严格按金融统计规范进行缺失标记、均值/中位数填充或特征降级，绝不伪造信号。
  3. **另类数据与 LLM 情绪限额**：规范新闻/论坛情绪词典及本地大模型（Ollama）的抽取逻辑，严格限制单次批量推理超时与标的条数，确保在无大模型环境下平滑降级至词典模式。

### Phase 4: 自适应三屏障标签与做空管理 (Labeling & Weighting)
* **优化目标**：优化预测目标质量，准确映射真实交易盈利空间与借券做空成本。
* **具体重构方案**：
  1. **完整三屏障 (Triple-Barrier) 标注**：引入基于 ATR (平均真实波动幅远) 的自适应动态止盈屏障、止损屏障与时间退出屏障，替代单一的未来收益率划分。
  2. **融券成本与借券管理集成**：将做空管理模块（Borrow Manager）的实时借券费率与做空可用性真正注入标签构建与样本权重计算中，自动对高做空成本或不可借券标的施加权重惩罚。

### Phase 5: 模型训练、概率校准与过拟合防御 (Model Fitting)
* **优化目标**：提高预测概率的可靠性，防范多重测试过拟合。
* **具体重构方案**：
  1. **真实夏普驱动的 Gamma 校准**：重构共形概率校准算法（CQR），放弃固定二次函数拟合，改用验证集实际风险调整后收益（Sharpe Ratio）作为目标效用函数，搜索最优校准参数 Gamma。
  2. **试验次数 (num_trials) 透传**：记录机器学习网格搜索与交叉验证过程中的实际超参组合尝试总数，并严格写入阶段上下文（Context），为下游 DSR 审计提供完整证据链。

### Phase 6: 运筹学仓位优化与集中度约束 (Position Sizing)
* **优化目标**：求解物理可行且风险可控的最佳资产配置比例。
* **具体重构方案**：
  1. **彻底移除调试代码**：清理所有生产环境中的日期剪裁与测试断言残余，确保回测与实盘运行全量时间序列。
  2. **拥挤度与集中度硬约束生效**：将 MLOps 拥挤度上限指标（`enforce_crowded_allocation_cap`）真正接入凸优化求解器（Convex Optimizer）与 HRP（层次风险平行）模块，作为全局资产权重的约束上界。
  3. **Black-Litterman 视角与协方差收缩**：采用稳健协方差估计（Shrinkage Covariance），结合市场 Regime 状态动态调整贝叶斯先验置信度。

### Phase 7: 有限状态机 (FSM) 高保真物理回测 (Execution Backtest)
* **优化目标**：真实还原物理世界中的交易摩擦、资金限制与订单执行延迟。
* **具体重构方案**：
  1. **$T 	o T+1$ 订单队列重构**：将撮合逻辑彻底迁移至下一交易日订单队列机制。根据 $T$ 日收盘后生成的视角与权重，在 $T+1$ 日开盘价或 VWAP 价格执行撮合，严格杜绝同日成交的未来语义。
  2. **高保真物理摩擦模拟**：集成非线性平方根市场冲击滑点模型、最小整手交易截断（如 A 股 100 股）、卖出印花税、佣金最低收费以及停牌/涨跌停无法成交的硬限制。
  3. **停牌与退市强制清算账本**：对持仓期间遭遇退市的标的实施残值清算计提，对长期停牌标的实施流动性减值，保持交易账本的资金守恒（1 元红线校验）。

### Phase 8: 风险审计、夏普惩罚与黑天鹅压测 (Audit & Stress Test)
* **优化目标**：建立严格的策略上线前置审计门禁。
* **具体重构方案**：
  1. **降阶夏普比率 (DSR) 真实惩罚**：基于 Phase 5 透传的真实 `num_trials` 和收益率高阶矩（偏度、峰度），精确计算多重尝试过拟合惩罚后的 DSR 统计显著性。
  2. **压力测试一票否决权**：将历史黑天鹅极端行情压测（如 2015 年股灾、2020 年流动性危机）的风险指标纳入审计硬门禁，压测不通过直接触发策略阻断。

### Phase 9: 实盘 MLOps、影子对账与物理硬杀伤 (Live MLOps)
* **优化目标**：实现实盘运行态的实时监控、对账与紧急止损。
* **具体重构方案**：
  1. **影子对账与硬杀伤联动**：每日收盘后比对 FSM 理论持仓与券商 API 返回的真实持仓。若平均绝对误差（MAE）或偏离金额超过安全阈值，系统必须自动触发物理硬杀伤开关（Hard-Kill Switch），停止次日自动化下单并拉响紧急告警。
  2. **概念漂移 (PSI/KS) 监测与重训提案**：监控特征与预测分数的分布漂移，触发重训信号时仅生成更新提案，保留人工复核接口。

### Phase 10: CIO 多智能体治理与安全参数提案 (CIO Reporting)
* **优化目标**：引入大模型决策评估，实现安全的参数闭环治理。
* **具体重构方案**：
  1. **真实数据聚合与 Prompt 注入**：移除所有 Mock 评估数据，将 Phase 7 真实净值、Phase 8 审计摘要与 Phase 9 漂移指标注入大模型上下文。
  2. **参数提案白名单机制**：LLM 或自动化调优系统生成的参数调整指令只能作为待审提案（Proposal）存盘，必须经过范围白名单与幅度限制校验，严禁直接覆写生产配置文件。

### Phase 11: 交互式投顾与安全降级网 (Interactive Advisor)
* **优化目标**：生成清晰的交易指令、建仓区间与止盈止损建议。
* **具体重构方案**：
  1. **审计失败安全降级**：前置阶段任何审计门禁未通过或对账异常时，系统强制将 Phase 11 降级为仅观察模式（`OBSERVATION_ONLY`），锁定所有买入指令。
  2. **四阶段动态决策链输出**：整合选择、建仓、持仓与止盈止损的专家链矩阵，输出包含明确价格区间、摩擦估算与归因分析的双语报告。

## 三、 系统架构与基础设施升级方案

### 3.1 统一配置管理与白名单治理
* **配置解耦与集中化**：将散落在各个阶段目录下的 `config.py` 硬编码参数统一收敛至根目录 `Main/default_param.yaml`。
* **参数变更审批流**：建立生产参数白名单校验机制，所有运行时参数覆写必须提供签名与修改日志，支持一键回滚至历史安全配置。

### 3.2 运行态缓存指纹与热加载失效机制
* **四元组运行指纹**：生成由 `Git Commit Hash` + `Config Hash` + `Data Manifest Hash` + `Schema Version` 构成的复合指纹。
* **自动热重算**：阶段缓存加载前强制比对当前指纹，若代码、配置或底层数据发生任何变动，缓存自动失效并触发全链路重算，杜绝旧缓存污染新逻辑。

### 3.3 阶段拓扑 DAG 与数据契约 (Schema Contracts)
* **DAG 拓扑守护**：在主控引擎启动前运行拓扑结构校验器，检查 Phase 1 至 Phase 11 的依赖闭包，严禁出现循环依赖与跳阶运行。
* **契约严格断言**：强化阶段间数据总线（Data Bus）的 Schema 契约校验，不仅检查 Dataframe/Tensor 的键名存在性，同时强制校验数据类型、数值范围与时间连续性。

### 3.4 资源预算分配与混合加速规范
* **自适应算力分配器**：系统初始化时自动探测 CPU 核心数、内存容量与 GPU 可用性，动态生成并行计算、数据加载与优化求解的资源预算，防止多进程过度订阅导致内存溢出。
* **C++/Cython 混合计算回退机制**：为核心密集型计算（如 FSM 逐日撮合、密集矩阵卷积）提供 C++/Cython 加速扩展，同时保留数值完全等价的 NumPy/SciPy 纯 Python 回退路径。

## 四、 质量保障、测试体系与验收标准

### 4.1 单元与集成测试 (Unit & Integration Tests)
* **测试覆盖率**：全量运行自动化测试套件，确保核心工具函数、契约校验与运筹求解器的单元测试覆盖率达到 100%。
* **DAG 拓扑闭环**：验证 Phase 1–11 能在非交互模式下无缝单向流转，无报错断裂。

### 4.2 未来扰动不变性测试 (Future Perturbation Invariance Test)
* **测试方法**：在历史数据末端（$T+1$ 至 $T+N$ 日）人工注入随机价格噪声与极端波动。
* **合格标准**：运行流水线后，$T$ 日及之前产生的所有特征张量、预测概率与目标仓位权重必须保持 0 差异（完全静态不发散），绝对证明系统无未来函数。

### 4.3 缓存指纹与可复现性检验
* **测试方法**：修改配置文件中的任一参数或提交新的 Git 代码，再次拉起流水线。
* **合格标准**：系统能精准识别缓存指纹不匹配，拒绝热加载旧缓存，并自动重新触发该阶段及其下游的完整计算。

### 4.4 对账偏差与物理杀伤模拟测试
* **测试方法**：在 Phase 9 模拟测试中，人工注入 5% 的持仓偏差向量或模拟网络断线导致的部分成交。
* **合格标准**：系统必须在 1 秒内捕获持仓不一致，抛出严重级别的告警日志，并成功调用物理硬杀伤接口，关闭后续交易指令生成。
