# Quant-Ultra 8-3 工程审查与升级方案

版本日期：2026-08-03  
适用分支：`8-3-improve`

## 1. 审查结论

当前工程拥有较丰富的量化组件，但“代码存在”“旁路增强脚本存在”和“正式主链已启用”长期混在一起。此前正式编排只到 Phase 9，Phase 10 使用 mock 指标，A股/ETF分析游离于阶段之外；日志存在历史乱码，两个主编排器并存，缓存缺少代码/配置/数据指纹绑定。因此项目适合研究验证，尚不能直接视为可无人值守运行的生产投资系统。

本次第一轮修复把正式阶段定义扩展到 Phase 11：Phase 10 只消费真实上下文证据，Phase 11 负责候选建议和持仓交互；根目录 `main.py` 作为唯一一键入口。所有原规划文件已补充“正式主链、旁路原型、缺失、验收”状态。

## 2. 金融量化投资专家审查

### 2.1 数据与可交易性

- 退市标的回流和 PIT 数据总线方向正确，但动态指数成分、财报修订版本和真实可获得时间仍不足。
- 数据完整性哈希只能证明本地内容未静默变化，不能证明第三方行情绝对真实；应增加跨源价差、复权一致性和交易所日历对账。
- A股需要明确处理停牌、涨跌停、ST、除权除息、申赎、ETF折溢价和最小交易单位。

### 2.2 研究方法

- 新增走步回测已具备 `close[t] -> open[t+1]` 和未来扰动不变性测试，这是可信基线。
- 原 Phase 7 仍有同日权重/价格语义，应迁移为订单队列；未迁移前不得使用其绩效作为无未来函数证据。
- 参数自适应必须限定于每折训练期，最终保留永不参与选择的 holdout；多次试验需用 DSR/PBO 控制数据窥探。

### 2.3 组合与风险

- BL、稳健协方差、风险平价和凸优化组件齐全，但 HRP、校准概率和正式优化器之间仍未形成单一可追踪链。
- 仓位建议应同时受波动目标、流动性容量、行业预算、单票上限、换手成本和账户整手约束。
- 止盈不是独立收益来源，应与止损、再平衡和机会成本共同回测；报告必须同时展示未止盈基准。

### 2.4 实盘治理

- PSI/影子对账可触发重训，但自动资金切流风险过高。模型生成的参数只能成为提案，不能直接覆盖生产配置。
- 上线门禁至少包括：数据新鲜度、跨源一致性、账本平衡、压力测试、样本外表现、成交容量和人工批准。

## 3. 计算机领域专家审查

### 3.1 架构问题

- `Main/main.py` 与 `Main/main_engine.py` 重复，配置默认值散落，容易产生不同运行结果。
- `enhance_dlc` 是旁路代码仓，缺少显式 feature flag、接口合约和集成测试。
- Phase 10 原实现包含 mock 指标和自动安装行为，不符合可复现、安全的生产原则。

### 3.2 可靠性与可观测性

- 阶段缓存需要加入 `git_hash + config_hash + data_manifest_hash + schema_version`，否则旧缓存可能污染新代码。
- 阶段异常不应在深层库函数直接退出进程；应返回结构化失败，由编排器统一决策。
- 报告、数据、模型、参数和交易信号需要同一个 `run_id` 串联。

### 3.3 测试与供应链

- 保留确定性单元测试、未来扰动测试，并增加阶段 DAG、循环依赖、契约覆盖和缓存失效测试。
- 依赖应锁定版本并生成 SBOM；Cython 扩展需要 CI 构建轮子，同时保留数值等价的 NumPy 回退。
- 密钥只允许来自环境变量/密钥管理，不得写入 `.env` 后提交。

## 4. 第二轮代码迭代范围

以下内容在第一次 GitHub 同步后实施：

1. **阶段 DAG 与一键启动安全检查**
   - 新增编排验证器，检查 Phase 1–11 顺序、依赖闭包、输入/输出契约覆盖和循环依赖。
   - 统一启动前检查并生成 `startup_manifest.json`。
2. **缓存可信度**
   - 新增运行指纹：Git、配置、Python、阶段列表；缓存元数据记录指纹，不匹配则拒绝热加载。
3. **Phase 10 安全参数提案**
   - 新增严格白名单和幅度限制的 `parameter_proposal` 校验器。
   - 只生成待审提案文件，绝不直接修改配置或自动切流。
4. **Phase 11 报告合约**
   - 候选报告加入 CIO 决策、数据证据路径和生成时间；若 Phase 10 为 `HOLD_FOR_REVIEW`，只输出观察名单，不输出买入动作。
5. **测试**
   - 增加 DAG、指纹失效、参数提案拒绝、Phase 10 缺证据拦截、Phase 11 降级行为测试。

## 5. 后续版本路线图

- `python main.py --non-interactive` 能按同一 DAG 启动 Phase 1–11。
- 所有阶段有合约、独立报告和统一运行指纹。
- 没有 mock 数据进入投资结论；缺证据时系统明确降级或停止。
- 所有参数调整是可验证、可审批、可回滚的提案。
- 单元测试、未来扰动测试、DAG测试、UTF-8读取和 `git diff --check` 全部通过。
