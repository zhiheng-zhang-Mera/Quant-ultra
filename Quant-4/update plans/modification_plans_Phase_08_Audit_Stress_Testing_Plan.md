# Phase-08 全向修改计划书：历史极端场景重放与系统抗脆弱审计

## 1. 现存系统缺陷剖析（尖锐审计）
* **单一时序的温水煮青蛙**：仅在连续的历史自然时序上做单一回测，容易掩盖策略在极端非线性冲击下的瞬间爆仓风险（如“黑天鹅”事件）。
* **统计宽容度过高**：当前的 Stress Test 只是简单的画图，缺乏对回撤恢复天数（Drawdown Duration）、极值回撤置信度（Conditional VaR）的硬性不通过拦截。

## 2. 全向改造计划与设计架构
### A. 历史极端情境精确重放引擎 (Historical Regimes Replay Engine)
* 精准切片并锁定历史上的重大宏观灾难节点，进行“高频段、大跨度”的专项压测重放：
  1. **2008 环球金融海啸**：验证系统在全市场极度恐慌、股债双杀、流动性枯竭期间的防御力。
  2. **2015 杠杆牛市崩盘**：模拟多股无量跌停、无法卖出平仓时的极端滑点流动性黑洞。
  3. **2020 COVID 熔断危机**：验证市场波动率瞬间飙升至历史极值时，策略组合的自我清算机制。
  4. **2024 年初微盘股流动性踩踏**：专项测试小市值暴露在拥挤踩踏下的回撤表现。

### B. 参数化风险因子冲击 (Parametric Factor Shock Test)
* 在不依赖历史时间轴的情况下，对当前的持仓组合进行人工合成的因子冲击：
  * **系统性 Beta 冲击**：模拟大盘瞬间下跌 5%, 10%, 15% 时，组合的净值敏感度。
  * **行业轮动崩塌**：将某一核心行业成分股的波动率瞬间拉高 300%，模拟单一板块暴露暴雷。
  * **资金断流与借贷利率飙升**：将融券及融资利率暴增至 20%，测试杠杆成本对收益的吞噬。

### C. 基于 Bootstrap 的策略覆盖度测试 (Bootstrap Coverage Test)
* 使用 **Block Bootstrap (块重采样)** 方法，对历史收益率序列进行 1000 次重构重采样，生成 1000 条合成净值曲线。
* 计算 99% 置信度下的 **Expected Shortfall (ES / CVaR)**。如果组合的 ES 超过风控红线（如最大回撤预期 > 15%），回测直接出局并硬性拦截，禁止上线。

## 3. 具体修改步骤与代码骨架
1. 重构 `stress_test.py`，加入 `ScenarioReplay` 类，定义上述极端区间的起止日期及流动性衰减系数。
2. 在 `step8_audit_stress_test.py` 中，执行块重采样 Bootstrap 检验。
3. 任何压测指标未达到阈值，通过 `sys.exit(1)` 中断 CI/CD 流水线，实施硬性拦截。

- **仅旁路原型**：区块 Bootstrap/ES 与增强场景位于 `enhance_dlc/phase_08_enhance.py`，未进入正式门禁。
